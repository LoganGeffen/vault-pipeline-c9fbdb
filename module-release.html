1 · Follow the release map

A new module has three release destinations. The manifest updates the registry automatically. The backend and frontend copies of the account-tier policy require separate releases.

3 · The training module

Training Echo accepts text and returns training_echo.csv with the original text and its character count. It uses Python 3.11 and the standard library. It is deliberately not a scientific model.

modules/training_echo/
  manifest.yaml       input, output, runtime, enabled, visible
  requirements.txt    empty: no third-party dependencies
  run.py              input → exact CSV output
  validation.json     known input and invalid case
  assert_output.py    verify contents, escaping and count

MODULE_ACCESS.training_echo = "silver"

Open the prepared module folder. The prepared starting state is disabled and hidden, with Silver as the example minimum tier. Validation uses text containing commas and quotes to check real CSV escaping; an empty input must fail.

4 · Recording route

  1. Start with the proposed files.

    Show the module implementation, manifest, dependencies, validation fixture and assertion, plus the deliberate Silver entry in MODULE_ACCESS. Briefly show local acceptance; the existing Vault walkthrough covers the detailed testing flow.

  2. Take the change through a PR.

    Show the branch and push, PR diff, exact-head checks and review, then merge through the release-owner path. Initial release is part of the recording, not an off-camera prerequisite.

  3. Follow all three release destinations.

    Match the automatic registry release’s actual checkout SHA to the intended merge. Verify deployment prerequisites, deploy the intended submit-job policy and publish the matching frontend. A green registry release alone is not completion.

  4. Enable and briefly test the module.

    The prepared module starts disabled and hidden. Change enabled and ui.visible to true through a manifest PR and registry release. Inspect the live catalog, run one distinctive input and open the expected CSV. Keep this test short.

  5. Change manifest settings.

    Change the title or description and release ui.visible: false through a PR. Show the catalog effect, then restore visibility for the access demonstration. Hiding affects discovery; it does not revoke backend execution permission. Manifest-only changes to an existing slug need the registry release, not a policy deployment.

  6. Change the tier and prove its effect.

    Edit MODULE_ACCESS.training_echo from Silver to Gold, show the follow-up PR and checks, then merge, deploy submit-job and publish the matching frontend policy. With the module enabled and visible, show a Silver organization denied with no new job and a Gold organization allowed. A missing menu entry alone does not prove backend enforcement.

  7. Disable new submissions and close out.

    Release enabled: false through the manifest PR flow and demonstrate that new submissions are blocked. Leave the training module disabled and hidden; retain successful jobs and results as evidence. Show the final settings and distinguish them from the earlier demonstration states.
